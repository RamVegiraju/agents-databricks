# 03 · Load test a managed Agent Bricks agent

This sample deploys a real inventory assistant with the Agent Bricks managed
`DurableAgentServer`, then uses the published `databricks-agentbricks[loadtest]==0.8.0`
CLI to test `/api/invocations`. The OpenAI Agents SDK calls a Databricks model service
and a read-only local inventory tool. Inventory is synthetic; the agent creates no
orders or shipments.

## What you need

- Python 3.11+, `uv`, and Databricks CLI 1.20+
- A Databricks CLI profile you explicitly choose for the target workspace
- Permission to create an App and use an existing `system.ai` chat model service
- Workspace support for the Agent Bricks managed Runtime Store

Run from the sample directory. Replace `<profile>`, `<model-service>`, and `<name>`
with values from your workspace. The deployment name must be unique in that
workspace and have at most 17 lowercase letters, digits, or hyphens.

```bash
cd pro-code/03-agent-load-test
databricks auth profiles
databricks ai-gateway list-model-services --parent schemas/system.ai --profile <profile> --output json
python3 scripts/select_model.py <model-service>
uv sync --default-index https://pypi.org/simple
uv sync --project cli --default-index https://pypi.org/simple
uv run --frozen --project cli agentbricks --profile <profile> doctor .
uv run --frozen --project cli agentbricks --profile <profile> deploy <name> \
  --source . --instances 1 --pip-index-url https://pypi.org/simple/
```

Choose a listed model service that supports `mlflow/v1/chat/completions` and tool
calls. `select_model.py` updates the model binding, App environment, and local
fallback together. The deploy command creates `agent-bricks-<name>` and provisions
its managed Runtime Store. It binds the existing model service and grants the App
identity access. It does not create a separate model endpoint, Session Store, or
Memory Store. Each inventory request remains independent.

`deploy <name>` records that name in `agent.toml` and may write workspace-specific
Runtime Store environment values to `app.yaml`. Keep those generated values out of
commits when sharing this sample with another workspace.

The CLI and App use separate Python environments. If your environment needs a
private package index, replace the PyPI URLs with your index. Local `uv.lock` files
are generated by `uv sync` and are not committed.

## Run your own end-to-end test

The smoke command sends a real nonstreamed invocation and checks the inventory tool
result. The load test sends one excluded warm-up and up to ten measured requests,
with at most two in flight. A run can extend past the 60-second dispatch limit while
active requests finish. Model and App charges apply.

```bash
mkdir -p private
uv run --frozen python scripts/smoke.py <profile> agent-bricks-<name> private/smoke.json
bash scripts/loadtest.sh <profile> agent-bricks-<name> my-first-run
```

To run the published CLI directly, use a new run name:

```bash
mkdir -p results/my-cli-run private/my-cli-run
uv run --frozen --project cli agentbricks --profile <profile> --output json \
  endpoint loadtest agent-bricks-<name> \
  --path /api/invocations --requests requests.json --sse \
  --concurrency 2 --max-duration 60 --max-requests 10 --timeout 50 \
  --report-dir results/my-cli-run/report \
  --save-responses private/my-cli-run/responses.json
uv run --frozen python scripts/check_results.py \
  results/my-cli-run/report/summary.json private/my-cli-run/responses.json
```

Open `results/my-first-run/report/index.html` for the native HTML report. The
`summary.json` records counts, latency, answer-text time to first token, throughput,
token usage, and errors. The response capture in `private/` contains real prompts
and answers; do not commit it. Use fresh run names and smoke filenames.

For a full one-minute dispatch window, omit `--max-requests` and use new output
paths. The CLI drains requests still active at the 60-second mark.

The three prompts cover a missed deadline, a feasible split, and a shortage. The
inventory tool subtracts reservations and returns stock by warehouse and transit
estimates. `SAMPLE_OUTPUT.md` shows the managed response shape. `VALIDATION.md`
records measured runs; short runs do not establish sustained capacity.

For local development, set `DATABRICKS_CONFIG_PROFILE=<profile>` explicitly, then
run `uv run --frozen python -m runtime.main`. The local managed runtime stores
invocation state in process; a deployed App uses a persistent Runtime Store. Offline
checks are `uv run --frozen ruff check .`, `uv run --frozen ruff format --check .`,
and `uv run --frozen python -m pytest -q`.

When finished, stop App compute while retaining the deployment and Runtime Store:

```bash
databricks apps stop agent-bricks-<name> --profile <profile>
```
